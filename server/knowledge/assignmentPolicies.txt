Developer Assignment & Workload Policies

1. Skill & Role Affinity:
   - Assign tasks only to developers whose technical skills and primary role match the task requirements.
   - For frontend tasks (React, Tailwind, CSS), prefer Frontend developers.
   - For backend/API tasks (Node.js, Express, MongoDB), prefer Backend developers.
   - For database/infrastructure tasks (SQL, Docker, Redis), prefer Database/DevOps developers.
   - For test suites and QA, prefer QA developers.

2. Leave & Availability Constraints:
   - Developers marked as on leave or unavailable MUST NOT receive any tasks under any circumstance.

3. Maximum Capacity Limit:
   - Developers with 3 or more active tasks are considered overloaded and are disqualified from new assignments.

4. Workload Balancing:
   - When multiple developers are technically qualified, assign the task to the eligible developer with the lowest current active task count.

5. Priority Dispatch:
   - High-priority and critical-path tasks must be assigned to the most experienced available developer in that domain.

6. Transparency & Auditability:
   - Every single task assignment MUST include a concise `assignmentReason` justifying why that specific developer was chosen over others.
